Before starting

The need and my role

The need

Design a consistent infrastructure for a fictional medical environment where directory, addressing, name resolution, web publishing and monitoring services do not rely on a single component.

My role

I completed the project individually from start to finish: requirements analysis, network architecture, IP addressing plan, service configuration, technical checks, documentation and final presentation.

Combine Windows and Linux services in a clear architecture.
Separate uses with VLANs and organise the related routing.
Plan continuity for DHCP and web services within the laboratory.
Centralise monitoring, logs and the technical inventory.
02

Why I chose this approach

The chosen solution

Segmented architecture with specialised services

The selected approach separates network and system functions: VLANs for logical isolation, Active Directory with DNS and DHCP for infrastructure services, web servers behind a load balancer, then Zabbix, Graylog and GLPI for operations. A formal comparison with other architectures was not documented in the initial project.

Eighteen VLANs organise the different uses within the laboratory.
Active Directory provides the directory, with DNS and DHCP services.
Two HTTPS web servers sit behind a load balancer.
LACP combines network links in the laboratory.
Zabbix monitors resources and Graylog centralises logs.
GLPI manages the inventory and equipment tracking within the project scope.

Looking back

Limits and improvements

Security and operation

  • Logical segmentation with VLANs.
  • Web publishing protected with HTTPS/TLS.
  • Logs centralised in Graylog.
  • Central directory for identity management.

What I would improve

  • The context is fictional and does not reproduce every constraint of a real medical organisation.
  • RPO/RTO objectives and failover times have not yet been recorded as measurements.
