01

Before starting

The need and my role

The need

Make language models usable without a cloud service and with limited hardware, while understanding the interactions between virtualisation, a Linux service, a container, the network and an API.

My role

I sized and installed the Rocky Linux VM, deployed Ollama and the models, installed Docker, connected Open WebUI, configured network flows and validated the solution in the command line and browser.

Run the complete platform with 2 vCPU and 8 GB of memory.
Select models compatible with the available resources.
Make the Ollama API reachable by the Open WebUI container.
Avoid presenting laboratory network exposure as a production architecture.
02

Why I chose this approach

The chosen solution

Ollama as the local engine, Open WebUI as a containerised client

Ollama provides a straightforward service for downloading and running models locally, while Open WebUI provides a browser interface separate from the engine. Compact models were selected to match the available 8 GB of RAM.

A Rocky Linux 9 virtual machine is hosted on VMware ESXi.
Ollama runs as a Linux service and exposes its API on port 11434.
Phi-3 and Llama 3.2 3B are stored and run locally.
Open WebUI runs in a Docker container and listens on port 8080.
The container calls the Ollama API to list and query models.
FirewallD limits access to the network flows required by the laboratory.

05

Looking back

Limits and improvements

Security and operation

  • Exposing the API on `0.0.0.0` simplifies the laboratory but increases the exposed surface.
  • In production, the API should remain private or sit behind an authenticated proxy with TLS and strict network filtering.
  • SELinux should remain in Enforcing mode; permissive mode can only be a temporary, documented diagnostic step.
  • The web interface and models require updates and backups under an operations policy.

What I would improve

  • Latency, tokens per second and peak memory have not yet been measured.
  • The selected resources limit the size and number of models that can run at the same time.
  • The laboratory does not cover GPU acceleration, high availability or federated authentication.
  • Response quality has not been tested with a reproducible evaluation set.
